# 客户端业务按钮图标刷新回归记录

验证时间：2026-11-03 至 2026-11-04，Windows / .NET Framework C# 4.8 编译器。

## 确认的触发链路

旧 `QueueButtonIconLoad` 在图标完成后更新目标控件，并调用
`ScheduleBusinessIconRefresh`。后者在 120ms 定时器到期后调用
`RenderCurrentVisiblePage`，重建当前业务页。分批图标完成会重复启动这个链路。
各变体渲染器清理并销毁子控件，部分渲染器还切换内容区可见性，因此这个刷新
不只是画图标，而是重复拆建整个页面。

使用 Git HEAD 中的旧生产方法和真实 WinForms 控件对照：

- 简化布局夹具中，有图标的四按钮页额外全页刷新 1–2 次；`SizeChanged=0`。
- 完整旧模板的 original 业务页中，四个图标按相反顺序分批完成，额外全页渲染 4 次。
  测试图标完成延迟为 450、590、730、870、1010ms 中对应的四个值。
- 无图标的 3/4/5 按钮简化布局场景全页刷新为 0。

这确认了异步图标完成后的整页刷新是已复现的触发链路；没有证据表明四个按钮
本身是独立的数量边界。此计数不是屏幕闪白时长。

## 修复

`src/ToolboxAdminApi-oneclick/client-template/ToolboxClient.cs`：

- 按图标 URL 和尺寸合并待更新控件，同一请求完成后更新所有存活目标。
- 请求键使用与现有图标缓存一致的大小写敏感比较；`Logo.png` 与 `logo.png`
  不会被误合并。新增用例先复现该问题，再改为 Ordinal 后通过；不同尺寸也独立缓存。
- 缓存命中直接应用到现有控件，异步完成通过 UI 线程应用并局部 Invalidate。
- 移除业务图标完成后的 120ms 整页刷新定时器。
- 统一移除各变体业务页、设置页、下载页和专用首页重建时对整个 `content` 容器的
  `Visible=false/恢复` 操作；这些页面现在只暂停布局并批量替换子控件，避免内容区
  在配置、导航或异步资源完成时产生可见闪烁。
- 当前页重复点击不再触发整页重建。
- 音频变体的窗口 `OnResize` 不再对常用工具页调用 `RenderCurrentVisiblePage()`；尺寸变化
  只执行现有控件的布局和局部重绘，避免滚动条/FlowLayoutPanel 重新计算时闪屏。
- 公共 `BeginContentRender/EndContentRender` 使用 `WM_SETREDRAW` 将内容区的绘制暂停到
  子控件批量替换完成，避免 `ClearChildControls()` 与重新添加按钮之间被绘制出空白帧。
- 软件目录图标不再因为旧目标已销毁而重建当前页面。
- 保留三次加载尝试、缓存及后续重试；关闭窗口和已销毁控件受到检查。
- 配置变更、页面切换和窗口尺寸变化继续使用原来的渲染入口；仅取消会造成闪屏的
  容器级显隐切换。

共享构建入口为 `app.py: make_client_exe()`；七变体均读取这一个模板。
本次没有修改构建入口、数据库或部署方式。已有其他工作区改动保留。

另外，真实 FlowLayoutPanel 夹具 12 组场景中，新增/移除控件、尺寸变化和
额外全页渲染均为 0。五按钮场景实际出现纵向滚动条，但没有位置变化。
队列方法运行夹具另覆盖共享 URL、失败重试、已销毁目标与三种加载顺序。

续测增加 41 组完整模板窗口场景，合计 104 组：

- 七变体均实际经过 `BuildNav` / `QueueShowPage` / `ShowPage` 切换；图标仍在加载时
  切换至同 URL 的新页面，新控件收到图标，旧控件已销毁。回到缓存页不再产生新请求。
- 切换至不相关的无图标页，旧图标回调不污染当前页、不重建该页。
- 80 按钮长页，先让窗口尺寸和滚动条布局收敛，再释放被测试门闩阻塞的图标请求。
  七变体滚动位置均保持 `-120 -> -120`，控件位置和句柄稳定。
- 使用实际主题切换方法验证 studio、tuner、vst76、xinggui 的浅色转深色；其余
  变体验证原有调色板刷新路径。portal 仍保留固定浅色规则。设置读写仅发生在临时目录。
- 图标请求尚未完成时关闭窗口，销毁后应用次数为 0，待处理批次清空，无未处理 UI 异常。
- 星轨专用首页分别放入 3/4/5 个按钮，验证宽屏双栏、窄屏上下布局、分页及切页返回。
- portal 最小窗口下分别验证三按钮一行、四按钮 3+1、五按钮 3+2；图标逐个到达后
  行数、控件实例、位置及滚动状态不变。

滚动条出现和窗口调整会触发现有尺寸刷新链路；它可能在初始布局阶段额外重建页面。
时序日志确认这发生在释放图标请求之前，不是新的图标回调循环。本次保留该兼容路径，
没有把所有窗口尺寸变化重构成局部布局。统计表的 0 指配置、导航、尺寸、主题等主动
操作完成后，异步图标返回所增加的全页渲染次数，不代表整个窗口生命周期从不渲染。

部分变体的原有业务控件会通过 `HideIcon` 或绘制模式隐藏图标；此样式保持原状。
例如 studio 普通文字按钮和 tuner/vst76 默认文字按钮不会因本修复被改成带图标按钮。
运行计数中的 icon 数量指加载到控件的数据，不等于可见图标数。

### 完整测试集及真实 HTTP 补测

2026-11-04 另执行 `unittest.defaultTestLoader.discover('tests')` 全量发现运行，
255 项耗时约 227 秒：245 项通过、8 项失败、2 项错误、0 跳过。
本报告上述图标、布局与生命周期测试均通过。全量运行开始后新增的真实 HTTP
测试单独执行 1 项通过，所以这两次运行合计覆盖 256 项，其中 246 项通过。

除上述三项既有失败，全量运行还暴露：

- 分段下载模板：云盘代理快速启动判断、备用 URL 的 CultureInfo 转换、永久下载
  失败传播三个断言失败，以及缺少 `IsPermanentDownloadFailure` 的一个错误。
  四项都已用 Git HEAD 的旧模板重新运行，分别得到同样的三个失败和一个错误。
- 公告邮件契约测试引用工作区外的 `ToolboxAdminApi-baota-source/app.py`，该文件缺失。
- 现有部署压缩包包含 `.log` / `.pyc`，版权打包断言失败。
- 现有部署包包含电竞音频功能标记，部署账户打包断言失败。

后面三项不以本次模板差异为输入；本次未改旁目录或重新打包这些部署压缩包。
没有为消除这些无关失败而扩大产品修改范围。

新增 `test_client_icon_http_windows.py` 在本机临时 HTTP 服务上运行真实生产

## 附件视频与验证边界

系统媒体解码器确认附件为 720×1280、约 7.000 秒。查看了 250ms 抽帧联系图，
并对开头进一步按 50ms 采样。开头约 0.00–0.65 秒可见四按钮页，按钮旁有图标；
约 0.70 秒起画面显示其他导航页，后面继续切页。寻帧有解码与播放等待误差，
这些时间仅用于识别场景。

抽样帧未捕获明确的空白闪屏帧，所以附件中的单次闪屏起止及持续时间尚无可靠
测量值。修复前后对照使用上述本地真实窗口渲染计数，未重现用户电脑上所有
显示器、DPI 和实际网络服务条件，也没有录制同机位
的修复后视频。完整生产联网视觉验收仍需用重新生成的客户端确认。
