# 后台审计与身份追溯迁移说明

本次版本采用增量 SQLite 投影，不删除或改写现有 `data/users.json`、邀请码字段和旧的 `data/security-audit.jsonl`。应用首次启动或执行迁移命令时会创建 `data/security.sqlite3`，并把旧日志标记为 `legacy` 导入；无法解析的行保留在 `details.legacyRaw`。

## 迁移

```bash
cd /opt/toolbox-admin
python3 audit_migrate.py migrate --data ./data
python3 audit_migrate.py verify --data ./data
```

迁移前应保留站点备份和 `data/` 备份。迁移脚本只新增投影和索引，核心 JSON 仍由现有应用读写。

## 回滚快照

回滚命令生成一个不修改线上数据的完整快照，可用于人工恢复：

```bash
python3 audit_migrate.py rollback --data ./data --snapshot /var/backups/toolbox-audit-snapshot
```

`audit_events` 使用 HMAC 链和不可变触发器；日志清理只写入隐藏索引，不删除原始事件。恢复时应同时保留 `security.sqlite3`、`security-audit.jsonl` 和 `security-pending.jsonl`。

## 签名密钥

默认密钥保存在 `security.sqlite3` 的本地元数据中。生产环境建议通过 systemd drop-in 设置持久的 `TOOLBOX_AUDIT_SIGNING_KEY`，并限制权限：

```bash
systemctl edit toolbox-admin
# [Service]
# Environment=TOOLBOX_AUDIT_SIGNING_KEY=从密钥管理系统注入的随机高熵值
systemctl daemon-reload && systemctl restart toolbox-admin
```

密钥变更会使历史链校验失败，因此升级、迁移和跨主机恢复时必须保持同一密钥。不要把该值写入仓库、工单、日志或前端配置。

## 数据兼容

- 邀请码删除只改变邀请码投影状态，`registrations`、`identity_history` 和 `audit_events` 永久保留。
- 新昵称、用户名、邮箱和手机号写入身份历史，搜索同时匹配当前值、注册值和历史值。
- 旧日志不满足结构化字段时保留原文并使用 `eventType=legacy`。
- 审计写入失败会落盘到 `security-pending.jsonl`，下次初始化自动补写；核心业务响应不因镜像日志失败而回滚。
